Placement algorithm
Changed
placement-progress.service.ts · adjustSessionFromAnswer
pure step(state, wasCorrect) → state | final → service method that mutates the session in place
binary search over LEVELS, first probe B1; 6 questions per level, 2 per category; 2nd mistake ends the level ✓
result: highest level passed, A1 if none; all six probed, C2 included → the level above the highest passed, capped at C2; C2 is never asked, passing C1 places at C2
at most 3 levels probed = 18 questions; progress.maxQuestionsRemaining counts down the worst case
The new result matches the "mastered + 1" rule in the #50 comment, so the exam and the onboarding picker store the same thing.

Question generation
Changed
question-stock.service.ts · llm/llm.factory.ts
runs in the background: the learner gets an unseen question meanwhile, or the one seen longest ago
one call per question → one call per cell, returning a batch (13 grammar, 10 vocabulary, 5 reading)
the JSON schema goes to Gemini with the prompt; the reply is parsed with generatedBatchSchema ✓ · retried once on a rate limit, a server error or a reply that breaks the schema ✓ · a malformed response never reaches a learner ✓
questions the cell already has are dropped; the rest are stored with sourceId = null, the cell's level and the time limit from ITEM_BANK.md ✓
once per cell: an in-memory lock per cell while a job runs, 10 minutes of rest after a failed batch or one that added nothing
LLM_PROVIDER = fixture: no network, no spend, writes no questions, so placement falls back to seen ones ✓ · gemini without LLM_API_KEY stops the api at boot
The lock and the rest period live in one API process, which suits the single replica decided in #44. The trigger is per learner, so a busy cell keeps growing as long as batches bring new questions.

A learner's courses, one per language: start one, set the daily goal, and the unified write path for the level.

Exports: CoursesService, used by PlacementModule
Uses: PrismaService
Referenced in #47#48#49#51#52
PlacementModule
apps/api/src/placement · PRs #71, #101, #104
The adaptive placement exam as a singleton resource per learner: a binary search over the levels, its run state in Redis, the server owning the clock.
Controller: PlacementController, /api/placement
Routes: POST / (start), GET / (question or result), POST /answers, DELETE / (quit)
Providers: PlacementService (start, get, answer, quit), PlacementSessionService (Redis keys, lock, run state), PlacementQuestionService (draw, shuffle once), PlacementProgressService (timeouts, scoring, result)
Imports: CoursesModule (setLevel), QuestionGenerationModule
Exports: all four services
Uses: PrismaService, RedisService
Referenced in #46#48#50#53#54
QuestionGenerationModule
apps/api/src/question-generation · PRs #69, #104
Keeps every (language, level, category) cell of the question bank stocked: when a learner is down to 3 unseen questions, it asks the LLM for a batch in the background.
Controller: none
Providers: QuestionStockService: restock(cell, unseen), one job per cell, a failed batch rests the cell
Imports: LlmModule
Exports: QuestionStockService, used by PlacementQuestionService
Referenced in #54#48
